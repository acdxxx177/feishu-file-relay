# Intake and persistence contract

Requirements: PRD F01–F03, F06, F08, F09, F11, F13 and §§3, 6, 8.

Callbacks are bounded to 1 MiB. Encrypted callbacks use SHA-256(Encrypt Key) as the AES-256-CBC key and the first 16 decoded ciphertext bytes as IV. Event signatures cover the original UTF-8 body, not serialized JSON. Verification Token, application ID, request timestamp (when supplied), and event creation timestamp are checked. When Encrypt Key is configured, both plaintext and encrypted events must carry valid signatures. URL verification is exempt from event timestamp/signature requirements but still checks Token and decrypts encrypted challenges. Production explicitly selects FEISHU_INTAKE_POLICY=platform, delegating user availability to Feishu while accepting only user p2p messages. Platform policy needs no uploader/chat allowlist and only the uploader can revoke a file, even if legacy admin IDs are present. Missing policy preserves legacy allowlist behavior; empty lists and unknown policies deny all intake. Legacy admins must also appear in the uploader list. Link listing always filters by the requesting uploader.

A short D1 transaction persists pending registration, recall tombstones, or command jobs before acknowledging the callback. This deliberate clarification of PRD §3.1 ensures an acknowledged callback survives termination before background work. Feishu network I/O runs after acknowledgement through waitUntil. Recall and registration are idempotent by message identity as well as event identity. All state transitions guard their previous status; an active or pending job cannot overwrite deleted state.

Source validation requires 206, exact bytes 0-0/total, a positive safe-integer total, and exactly one streamed byte. The one-byte probe has a total timeout bounded by eight seconds and UPSTREAM_READ_TIMEOUT_MS; cancellation cleanup is attached to waitUntil so a broken connection cannot block the guarded state transition. A source that ignores Range is rejected rather than assigned an estimated size. Unsupported small-file Range behavior remains a real-environment validation item (V2).

files adds next_attempt_at and lease_until to the PRD schema. Initial validation plus three retries use persisted minimum delays of 2, 10, and 60 seconds; Cron runs every five minutes, so deferred retries may happen later. Expiring leases recover terminated workers. bot_jobs is a minimal D1 outbox for commands and notifications, with bounded retry, expiring leases, and a deterministic Feishu uuid. It holds message text and source/public identities, never token or source bytes. The UUID prevents duplicate messages within Feishu's documented deduplication window; a crash after a successful send may still duplicate after that upstream window expires.

Successful validation and its publication notification are committed atomically. The publication sender rechecks active status. The transition to unavailable and its notification outbox insertion are also one transaction. Bot send failure never rolls back a valid file or deletion.

Token state lives only in isolate memory and the private relay-private-tokens-v1 Cache API namespace. Cache keys hash the app/base/secret configuration, preventing key rotation from reusing previous credentials. Source bytes and authorization headers never enter D1 or chunk responses. API redirects are rejected. Only confirmed HTTP404/410 are classified permanent; auth/403/429/5xx/network failures remain temporary pending verification of real Feishu business error codes.
