# VPS runtime contract

The Node entry is `main.ts`; application creation has no startup side effects. Production uses one process, `@hono/node-server`, in-process jobs and a remote Prisma/D1 repository. No Workers runtime API is reachable from the Node bundle. The legacy Worker tree is retained only for regression and rollback preparation.

First-download notifications are independently opt-in (`FIRST_DOWNLOAD_NOTIFICATION_ENABLED=false`). Browser metadata advertises capability only for eligible files; session creation and completion require the configured same Origin, bounded JSON, existing rate limits and no prefetch intent. `X-Download-Session` is an opaque memory-only token bound to file/version/size/save method. Canonical chunks advance a contiguous high-water mark only after verified EOF; duplicates, gaps, other sessions and raw transfers cannot contribute. At most 1,000 sessions live for 24 hours. Restart/expiry/capacity failure loses tracking, never download authorization. Native close success or a trusted Blob Save activation sends an independent completion request with up to ten minutes of bounded browser retry. These signals do not prove recipient identity, human intent, file opening, or Blob disk persistence.

Completion freezes server time and location before a primary D1 idempotent write. The public start/write operations consume the download budget, not control reserve. Durable notification jobs survive process restart; in-memory confirmation loss before durable commit may omit a notification. File availability is checked atomically when first recording the event; subsequent recall does not cancel an already-recorded historical notification. Counts and streaming semantics remain separate.

`TRUST_CLOUDFLARE_GEO=false` requires explicit enablement after proxy verification. With both `TRUST_PROXY` and `TRUST_CLOUDFLARE_GEO` enabled, `X-Relay-Geo-Trusted: 1` permits reading the three internal geographic headers regardless of the connection source. There is no application-level proxy IP allowlist. Nginx still checks original Cloudflare peer ranges through `$realip_remote_addr`, overwrites all internal values, and clears values from other peers. A caller reaching Node directly can supply the marker and geographic headers; this is an explicitly accepted deployment tradeoff. Decode the UTF-8 bytes carried through Node's Latin-1 header representation, validate bounded plain text, and persist only country/region/city. Raw Cloudflare/IP headers never authorize geographic data. Unknown or incomplete values degrade independently. Existing first-confirmation snapshots remain immutable after an upgrade.

Every public file read is authorized through `getDownloadFile`; control jobs use `getFile`, preserving reserved API capacity. Webhooks persist before acknowledgement. Tasks and notifications stay in D1; process memory is never the durable queue. Job completion is fenced by attempt and lease. Startup scans and non-overlapping polling recover work after crashes.

Card interactions at the same webhook use Feishu's signed modern callback envelope, including microsecond creation timestamps. Application processing reserves 2.4 seconds from entry for a confirmed D1 result. On a timeout it returns an uncertain-result toast and continues tracking the operation. The atomic D1 batch schedules the original-message update. See the [repository contract](../../db/context/vps-contract.md) for file and message ownership.

For signed `schema: "2.0"` / `card.action.trigger` callbacks, `X-Lark-Request-Timestamp` is an opaque, nonempty signature input, not a required Unix number. Its exact value, nonce and raw body remain covered by the signature. The mandatory signed body `header.create_time` enforces the configured freshness window (default five minutes), including future timestamps. Token and app checks remain mandatory. Other event envelopes retain the numeric request-header freshness check. This follows Feishu's [callback verification](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/receive-and-handle-callbacks) and [official Node SDK](https://github.com/larksuite/node-sdk/blob/main/dispatcher/request-handle.ts).

Sockets are observed independently of request-body completion. `safeNodeResponse` destroys a failing binary response before the Node adapter can append an error body. Length and EOF checks retain the final byte buffer until the upstream stream is verified. Client abort, source deadlines and shutdown cancel upstream work. Backpressure is bounded; source files are never persisted.

The optional cache is bounded at 64 MiB, five minutes, one completed chunk per file, and excludes complete small files. D1 is checked before every cache hit. Cache state grants no permission. The production proxy must disable cache, response buffering, temporary files and compression.

Readiness is loopback-only with shared 15-second results and blocked at Nginx; it always checks the actual socket. With `TRUST_PROXY=true`, download rate-limit keys use a single valid `X-Real-IP` from any connection source, falling back to the socket address when the header is missing or invalid. With the switch false or omitted, only the socket address is used. Generic forwarding headers remain ignored, and forwarding a loopback address does not grant readiness access. Legacy `TRUSTED_PROXY_IPS` environment values are ignored, including malformed values; they are no longer parsed or emitted by templates. This allows Docker address changes without configuration updates, but direct callers can choose their rate-limit identity when proxy trust is enabled. Global concurrency defaults to ten. Shutdown stops claims immediately, drains for up to 60 seconds, then aborts remaining work; expired leases permit recovery.

Docker targets Linux AMD64 and runs one non-root Node process with a read-only filesystem, injected environment and no file-content volume. Compose publishes only to host loopback, using a dedicated bridge with a configurable subnet/gateway; these network settings are independent of application proxy trust. The host proxy must overwrite X-Real-IP. Container liveness uses /health without D1; readiness must be checked inside the container. Compose's default 70-second grace exceeds the application's 60-second drain. No migration runs at build or startup. The environment generator only writes a blank/default template and refuses overwrites. CI verifies containers without production credentials or external-network access; version/manual publication to GHCR does not deploy the service.
