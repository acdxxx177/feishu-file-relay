# VPS runtime contract

The Node entry is `main.ts`; application creation has no startup side effects. Production uses one process, `@hono/node-server`, in-process jobs and a remote Prisma/D1 repository. No Workers runtime API is reachable from the Node bundle. The legacy Worker tree is retained only for regression and rollback preparation.

Every public file read is authorized through `getDownloadFile`; control jobs use `getFile`, preserving reserved API capacity. Webhooks persist before acknowledgement. Tasks and notifications stay in D1; process memory is never the durable queue. Job completion is fenced by attempt and lease. Startup scans and non-overlapping polling recover work after crashes.

Sockets are observed independently of request-body completion. `safeNodeResponse` destroys a failing binary response before the Node adapter can append an error body. Length and EOF checks retain the final byte buffer until the upstream stream is verified. Client abort, source deadlines and shutdown cancel upstream work. Backpressure is bounded; source files are never persisted.

The optional cache is bounded at 64 MiB, five minutes, one completed chunk per file, and excludes complete small files. D1 is checked before every cache hit. Cache state grants no permission. The production proxy must disable cache, response buffering, temporary files and compression.

Readiness is loopback-only with shared 15-second results and blocked at Nginx. Download rate-limit keys come from sockets or a trusted proxy's overwritten X-Real-IP. With TRUST_PROXY=true, loopback and explicitly configured TRUSTED_PROXY_IPS are accepted; the latter is an exact comma-separated IP list, not CIDRs or hostnames. Node BlockList matches IPv4-mapped IPv6 peers. The default list is empty for existing deployments. Generic forwarding headers remain ignored, and trusting a proxy does not grant readiness access. Global concurrency defaults to ten. Shutdown stops claims immediately, drains for up to 60 seconds, then aborts remaining work; expired leases permit recovery.

Docker targets Linux AMD64 and runs one non-root Node process with a read-only filesystem, injected environment and no file-content volume. Compose publishes only to host loopback, using a dedicated bridge with a configurable subnet/gateway; by default only that gateway is added to TRUSTED_PROXY_IPS. The host proxy must overwrite X-Real-IP. Container liveness uses /health without D1; readiness must be checked inside the container. Compose's default 70-second grace exceeds the application's 60-second drain. No migration runs at build or startup. The environment generator only writes a blank/default template and refuses overwrites. CI verifies containers without production credentials or external-network access; version/manual publication to GHCR does not deploy the service.
