# Public file download page

Recipients arrive from a shared link to save one file. The page is a single-file detail screen. The filename, availability and next action take priority. The design follows the Achromatic ledger app-screen direction with the project's local system fonts and teal accent. `src/browser/download.css` owns the light ground (#f3f5f6), white surface, ink (#172a35), accent (#075c70) and error (#a21b27).

Use a single centered surface with a wrapping filename, readable size and contextual download controls. Align the native language selector with the page heading and allow it to wrap on narrow screens. Use 48 px controls, visible keyboard focus, square edges and flat colors. Progress pairs a native meter with a localized percentage and exact byte counts. Status transitions and clipboard feedback have separate live regions. Preserve forced-color support and keep the interface usable without animation.

Localize the first HTML response, title, status, errors, compatibility help and accessible names in English, Spanish, Hindi and Simplified Chinese. Filenames remain user content. A manual choice overrides automatic detection. Switching languages updates the existing UI in place, including any pending save link. The server-rendered page communicates availability and a JavaScript requirement when scripting is disabled.

Opening the page reads no file bytes and never counts a download. A native picker runs in the activating click. Verified chunks stream to a tentative file and successful close commits it. Browsers without the picker may assemble a Blob through 20 MiB and require an explicit **Save file** action. Larger files offer **Copy link** and browser guidance. Automatic retries roll the current chunk back and preserve the open stream. A manual restart begins at byte zero. Unavailable pages explain the reason and next step once.
