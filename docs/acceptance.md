# 验收说明

对应PRD F01–F13、§11–13。只使用隔离测试消息；通过产品登记文件意味着公开分享，需预先确认允许外发。

## 本地

运行 `pnpm typecheck`、`pnpm test`、`pnpm test:large`。测试启动真实workerd、独立D1和Cache API，以mock覆盖飞书响应，不读取本地凭据。

普通测试覆盖签名/Token/加密/重放、去重/白名单、登记与机器人回复、撤回乱序和热缓存410、撤销权限、Range/If-Range/HEAD、错误回源、统计与限流。大文件以可重复生成的数据流建立原始SHA-256基准，再验证完整下载和真实取消后从实际偏移续传的SHA-256，不缓冲整个文件。

## 真实环境（需操作者配置）

1. 按[部署说明](deployment.md)配置测试应用、D1与域名，确认下载不需登录，/chunks/*与未知路径404。
2. 准备100 MiB、500 MiB、1 GiB原文件，上传前计算 `Get-FileHash -Algorithm SHA256 -LiteralPath '文件路径'`。另测小文件、JSON附件、中文与特殊字符名。
3. 生产platform策略由应用可用范围内用户单聊发文件，检查文件名/可信大小/22位ID/公开分享提示/撤销方式；群聊与机器人发送者不登记，不支持类型给提示。名单模式另在隔离环境验证非名单用户不登记。首次真实接入先验证允许公开的小文件，不自动进行大文件压力测试。
4. 每个已授权测试链接执行：

```powershell
$env:DOWNLOAD_URL = 'https://你的域名/f/测试链接ID'
$env:EXPECTED_SHA256 = '上传前原文件的64位SHA256'
pnpm smoke
```

脚本检查HEAD、完整下载与实际中断后的续传。不要用服务下载所得哈希替代原文件基准。还需在浏览器和常用下载工具验证中文名、缓存头、ETag/If-Range恢复行为。

5. 同地区重复下载，对比分片HIT/MISS与实际回源次数；不同地区分别测冷/热缓存、TTFB、吞吐。目标热缓存≤1秒、冷缓存≤5秒，以实测校准。
6. 热缓存时撤回，确认新GET/HEAD410。测试重复回调、先撤回后登记、上传者本人撤销成功、他人被拒绝；生产不配置管理员，名单模式的管理员另在隔离环境验证。区分仅自己删除与真正撤回。
7. 隔离环境验证429/5xx/网络故障503且不永久失效；确认资源404/410后410且只通知一次。记录真实业务错误码，不把全局鉴权问题误判为单文件失效。
8. 当前按已授权隔离环境的分阶段CPU方案验收，不为旧十路1GiB目标自动升级套餐或执行生产压力测试。本地十路回归不等于生产指标；每次扩大必须通过完整性、CPU和观测覆盖门禁。
9. 客户实际地区测试首字节，持续观测附件1/7/30天可读性，不承诺永久保留或全球命中。

每项记录日期、PRD/V编号、环境/地区、假设、实际状态/关键头/哈希、结论与调整。不记录凭据、file_key、完整Authorization或内容。区分本地通过、远程跳过、凭据缺失的阻塞项，见[验证日志](verification-log.md)。

## v1.2 浏览器分片补充验收

以[浏览器下载说明](browser-downloads.md)为新入口合同。原始二进制测试使用 `/f/:id/download`；HEAD `/f/:id`仍返回D1文件元数据。浏览器页面不计数、不回源，显式点击才传输。

- 真实浏览器分别验证原生选择器/写盘提交与≤20 MiB Blob保存；超过上限且不支持选择器时应提示换浏览器，不得构造整文件Blob。
- 观察每片独立请求和If-Match，断网恢复只重试失败片；取消不提交暂存文件。刷新或重启后重新开始。
- 在相邻两片之间撤回，下一片410；D1不可用时拒绝热缓存；文件版本变化412立即终止。
- 1/20/100/500/1024 MiB完整与页面内恢复逐个比对源SHA-256。模拟sink结果与真实浏览器验证分开报告。
- 仅按已授权4 GiB隔离预算测CPU，不升级套餐，不自动在生产运行大文件。每个扩大阶段必须先通过前一级；原始100 MiB CPU失败保留为历史事实。
