# Online test runner contract

`online-test.ts` runs only against a named isolated test Gateway on HTTPS workers.dev. Its ignored manifest identifies the account, Gateway, private mock Worker, D1, configuration and fake secret file. No credential is accepted on the command line. D1 is accessed through the installed Wrangler executable with `--command` as a separate execFile argument; no shell interpolation is used. SQL contains isolated fake fixture metadata only, never keys or credentials, and a copy is kept in ignored run-scoped files for inspection. Wrangler 4.156.2's remote `--file` path performs a bulk import and returns an import summary rather than SELECT rows, so it is not used by the driver.

Fixtures enter through the authenticated public Feishu webhook. Public URLs are parsed from `mock_replies.content`, rather than manufactured from D1 file IDs. Remote SQL only configures fake source fixtures and reads test evidence. Source requests, replies and control rows remain in the isolated test D1 for inspection.

The `.local/online-results.json` ledger persists a conservative 512 MiB response budget across invocations. An exclusive `.local/online-test.lock` prevents overlapping runner processes from creating separate budgets or exceeding concurrency; a stale lock is never automatically stolen. Each request reserves its maximum response size and atomically persists the charge before network I/O; canceled/resumed requests retain their full reservations, so restart cannot reclaim traffic budget. Actual received bytes are separately recorded. At most two HTTP requests run concurrently; download requests are paced below the configured per-IP rate limit. The runner does not upgrade account plans or deploy/delete resources.

Tests progress through 1 MiB, 20 MiB and, only after successful lower-size verification, 100 MiB. Unexpected platform errors or unstable lower-size transfers stop expansion. 500 MiB, 1 GiB and ten-way concurrency remain skipped on this Free-plan run. A cache observation records actual per-colo source counts; lack of a repeat HIT is reported as unaccepted caching, not silently considered proof of CDN behavior.

Before every size expansion the runner reads `.local/online-platform-limits.json` produced by the two-worker safe tail monitor. A matching Gateway/mock resource-limit outcome stops expansion even when the public Gateway has normalized the upstream failure to 503. Missing evidence is allowed; unreadable existing evidence fails closed. The parent orchestrator starts the monitor before this runner.

Failed cases and final reporting allow a bounded two-second tail grace period and refresh platform evidence, because an exceededCpu event can arrive after the HTTP body has already failed. The per-run report persists platformLimited and matching outcomes. Reply lookup uses SQLite instr rather than LIKE: the hosted D1 LIKE-pattern limit can reject long generated UTF-8 fixture names even when the lookup is semantically simple.

`--cancel-only` performs one separate 1 MiB cold-source probe without the normal size-expansion suite. It publishes a fresh fixture, configures a five-second source-header delay, and aborts the public request after 1.5 seconds. The same ledger, process lock and concurrency cap apply. A PASS requires an observed client abort plus every non-probe source request recorded as cancelled-before-headers with zero produced bytes. Missing or later cancellation evidence is SKIPPED with the raw sanitized outcome rows preserved, never reported as successful source cancellation. Caller cancellation is combined with the existing request deadline through AbortSignal.any.

All mock bytes use the shared absolute-offset fixture. Full/resumed bodies are hashed incrementally; only tiny bounded ranges are buffered. Completed integrity checks persist expected and actual SHA-256, kind, byte count and offsets before asserting equality. Reports include HTTP status, edge colo, byte count, outcomes and timings, never webhook request bodies, keys or authorization headers.

## Authorized browser architecture trials

The user separately authorized updates to the existing isolated resources and up to 4 GiB additional client-response reservations. --browser uses browser-online-results.json, browser-online-tail.jsonl and browser-online-platform-limits.json, retaining the old ledger and limits. All revisions share the new total budget and the existing exclusive lock; never reset reservations after a new build. Runs record artifact/config hashes and a checked 100% active Gateway version. Browser deployment first builds the complete isolated bundle, then deploys that exact artifact with --no-bundle. No new resource adoption, production route or production data is authorized.

Every candidate requires separate complete Gateway and ChunkEntry CPU sample coverage. Forwarding CPU alone does not establish total download viability. A pending RPC/cache pump can consume substantially more CPU than its public caller. Keep rejected functional candidates and platform outcomes. Whole-run limit reporting derives retained limits even when candidate-level flags reset. Only qualified candidates permit increasing file size; a full-transfer failure stops expansion. A later architecture or cache-policy revision may test new bounded candidates within the same remaining budget, with build identity and prior evidence retained.
