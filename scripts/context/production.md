# Production configuration contract

The user explicitly authorized real Feishu production deployment on dl.sinoballvalve.com in the existing Cloudflare account, independent production D1, four Secrets sourced precisely from ignored .env, and no account plan changes. Existing online mock resources must remain untouched. Production checks must not register synthetic files or send bot messages.

production-setup.ts accepts prepare/deploy/verify. Native parseEnv reads exactly .env and does not expand dollar variables or allow .dev.vars/process environment overrides of Feishu credentials. Only the four named Feishu keys enter ignored production-secrets.json and the deployed Secrets. PUBLIC_BASE_URL remains a normal variable. Never print authentication outputs, secret values, token responses, or raw child-process exception objects.

The root Wrangler config documents production routes and bindings; online-test and its generated configuration explicitly set routes:[] to prevent inheriting the production hostname. Deployment uses ignored production-worker.json with no routes or environments, absolute entry/migration paths, real transport and platform policy. The installed Wrangler force-enables DNS/origin overwrite in noninteractive custom-domain deployment, so the script attaches the domain separately with override_scope, override_existing_origin and override_existing_dns_record all false. Domain conflicts fail rather than replacing existing services. The default pnpm deploy must keep using this guarded path.

The local production manifest identifies the production D1 for safe retries. Missing manifests do not authorize adopting existing named databases or Workers; inspect existing resources before reconstructing a lost manifest. D1 receives only normal migrations, never testing-migrations. No destructive cleanup is automatic.

Production verification checks HTTPS, both challenge forms, invalid callback rejection, D1-only HEAD on an unknown ID, Secret names, transport/policy/D1 bindings, disabled workers.dev/previews, schema and record counts, and one real OAuth credential exchange from the local machine. It stores only sanitized configuration/results in ignored production-verification.json. Real Feishu event delivery and attachment/range/recall behavior remain separate manual acceptance; prior online mock CPU failures must not be relabeled as successes.
